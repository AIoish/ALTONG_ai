# 단일 점수 학습 진단

기존 C 실험의 긴급도·관련도 어댑터에 대해 학습에 쓴 사례와 검증 사례를
다시 추론했다. 새 학습은 하지 않았다. 각 모델은 별도의 기반 모델에 하나씩
로드해 두 어댑터 전환 오류 여부도 확인했다. 최종 테스트는 추론하지 않았다.

## 확인한 사실

긴급도 학습 원문 50개의 정답 분포는 1점 20개, 2점 9개, 3점 4개,
4점 11개, 5점 6개다. 관련도 학습 문맥 150건은 1점 100건, 2점 3건,
3점 6건, 4점 12건, 5점 29건이다.

각 점수의 첫 두 학습 사례씩 총 10건을 골라 진단했다. 두 모델 모두
10건 전부 1을 생성해 각각 정답 2/10이었다. 이 표본은 점수별로 고른
진단 사례이지 전체 학습 정확도나 독립적인 성능 평가가 아니다.
학습 사례에서도 점수를 제대로 구분하지 못하므로 단순한 검증 일반화 문제로
설명하기 어렵다.

단독 로딩 결과는 이전 C의 두 어댑터 전환 결과와 일치했다. 긴급도는
검증 원문 대표 8건, 관련도는 검증 24건을 확인했다. 전환 시 잘못된 어댑터를
사용해서 발생한 결과라는 증거는 발견하지 못했다.

| 작업·표본 | 점수 숫자 토큰 평균 NLL | JSON 문법·EOS 토큰 평균 NLL |
| --- | --- | --- |
| 긴급도 학습 표본 10건 | 2.0348 | 0.0005 |
| 관련도 학습 표본 10건 | 2.2754 | 0.0003 |
| 긴급도 검증 원문 8건 | 1.7050 | 0.0005 |
| 관련도 검증 24건 | 0.5774 | 0.0002 |

NLL은 정답을 입력한 상태에서 다음 토큰을 맞추는 음의 로그 확률이다.
단일 점수 JSON과 EOS는 이 토크나이저에서 8토큰이며 숫자는 그중 1토큰이다.
정답 숫자는 잘 못 맞추지만 나머지 7토큰의 형식은 매우 잘 맞춘다.
균등한 토큰 loss에서는 숫자의 학습 비중이 1/8에 불과하다.
그러므로 낮은 전체 loss나 24/24 JSON 준수만으로 올바른 점수 판단을
확인할 수 없다. 숫자 기여 부족과 정답 편향이 원인일 가능성을 지지하지만,
어느 쪽이 얼마나 기여했는지는 대조 학습 전에는 확정하지 않는다.

관련도 검증의 숫자 NLL이 더 낮은 것도 성능 개선의 증거가 아니다.
검증에도 1점이 24건 중 16건이어서 항상 1을 예측하는 모델이 유리해 보인다.

원시 진단은 outputs/runs/2026-10-03-qwen06-score-pilot-01/learning_diagnosis.json에
있다. 표본 선택 인덱스·ID·정답·생성 원문·숫자별 확률·토큰별 손실을 보존했다.
아래 명령은 별도 출력 파일 이름으로 실행한다. 기존 진단은 덮어쓰지 않는다.

```powershell
python -m filtering_training.quality.audit_score_learning --prepared-root filtering_training/outputs/v3_score_separation_01/prepared --runs filtering_training/outputs/runs/2026-10-03-qwen06-score-pilot-01 --output filtering_training/outputs/runs/2026-10-03-qwen06-score-pilot-01/learning_diagnosis.json
```

## 다음 비교는 원인을 하나씩 바꾼다

기존 C를 기준으로 같은 원본 데이터·분할·seed·스텝·모델·프롬프트에서
숫자 loss 비중만 높이는 실험을 먼저 비교한다. 예를 들어 이 8토큰 출력에서는
숫자 가중치 7·나머지 가중치 1, 가중치 합으로 정규화하면 숫자와 형식이
각각 절반을 차지한다. 이는 출발 가설이며 아직 구현·학습·채택하지 않았다.
숫자 토큰이 prompt 마스킹에서 제외되지 않는지, shift 후 정답 위치가 맞는지,
숫자 가중치만 실제로 바뀌는지 검사한 뒤 실행한다.

별도 실험에서는 토큰 loss를 그대로 두고 점수별 학습 샘플링만 바꾼다.
총 스텝 수를 고정하고 실제 뽑힌 점수 분포·중복 횟수를 기록한다.
관련도 2점처럼 기존 3행뿐인 점수를 반복하면 과적합할 수 있으므로
샘플링 개선을 새 독립 원문 확보와 동일시하지 않는다.
이 두 변경과 데이터 추가를 한꺼번에 섞지 않는다.

학습 표본의 숫자 예측이 개선되는지 먼저 확인하고, 같은 검증에서 긴급
오차단·오통과·숫자 정확도와 처리 시간을 비교한다. 검증 원문이 8개뿐이므로
최종 채택 근거로 사용하지 않는다. C가 학습 사례도 못 맞춘 상태에서
학습 시간을 무작정 늘리거나 모델 크기를 키우지 않는다.

## 새 보강 검수 묶음

outputs/v3_score_review_02/에 원문 8개·문맥 24건을 준비했다. 아직 미승인이다.
기존 모든 분할의 정보 창을 재사용하지 않았다. 지정한 유사 계열은 기존
학습 원문(자격 정보 노출, 가족 응급 연락, 면접 입장, 운동화 홍보)에만
연결했다. 모든 의미 유사성을 자동으로 검증했다는 주장은 하지 않는다.
같은 스페인어 연습 창에 유용한 학습 방법·상품 광고·농담을 대비시켰다.
동일 알림의 긴급도는 정보 창·무관 창·빈 창에서 유지한다.

세 문맥 묶음을 단순 추가하면 관련도 1점이 여전히 2/3이다. 이 자료는
새 주제와 대비 사례를 보강하기 위한 것이며 분포 편향까지 해결했다고
주장하지 않는다. 승인 후에도 기존 검증·테스트는 유지하고 새 묶음은
학습에만 넣는다. 첫 승인 묶음의 보류 기록도 그대로 보존한다.
