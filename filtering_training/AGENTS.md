# 파일 생성 규칙

- 새 파일은 용도에 맞는 하위 폴더에 만든다. 루트에는 패키지 설정과 공통 안내만 둔다.
- 현재 코드: `common/`, `generation/`, `preparation/`, `quality/`, `modeling/`.
- 현재 흐름에서 사용하지 않는 과거 실험 코드는 `legacy/`로 구분한다.
- 새 데이터 버전은 `outputs/`의 해당 버전 폴더에 후보·검수·확정·분할 자료를 모은다.
- 새 학습 실행은 `outputs/runs/<날짜-모델-실험>/`에 설정·가중치·평가 결과를 모은다.
- 일회성 관리 도구와 이동 기록은 `outputs/_maintenance/`에 둔다.
- 재사용할 실행 코드를 데이터·평가 결과 폴더에 흩어 놓지 않는다.

## 새 파일의 상단 기록

새 코드·문서에는 맨 위 2~3줄에 구체적인 용도와 최초 생성일을 적는다.
날짜는 사용자 시간대 Asia/Seoul 기준 `YYYY-MM-DD`로 기록하고, 수정 시 최초 생성일을 바꾸지 않는다.

Python 예시:

```python
"""용도: 필터링 알림 후보의 점수 분포와 중복을 검사한다.
생성일: 2026-10-03
"""
```

Markdown은 HTML 주석, PowerShell은 `#` 주석 등 파일 형식에 맞는 주석을 사용한다.
실행을 위해 첫 줄이 고정된 파일은 필요한 첫 줄 다음에 기록한다.

JSON·JSONL·CSV·바이너리 모델·자동 생성 라이브러리 파일은 상단 설명 때문에 형식을 깨뜨리지 않는다.
이 경우 해당 버전·실험의 기존 `manifest.json`, `run_config.json` 또는 `README.md`에
파일의 용도와 생성일을 기록한다. 용도별 설명을 함께 관리하고 불필요한 개별 설명 파일은 늘리지 않는다.
직접 만드는 생성 도구에도 이 기록을 남기는 기능을 포함한다.

## 범위와 보존

- 이 지침은 필터링 학습 폴더에 적용한다. 브리핑 코드를 변경하지 않는다.
- 파일 이동 시 import·기준 경로·실행 명령을 확인하고 필요한 검증을 한다.
- 기존 데이터·검수·가중치를 새 실험으로 덮어쓰지 않는다.
- 파일 삭제 전에는 사용자에게 대상과 영향을 먼저 설명한다.
