# 관련도 데이터 정리와 다양성 검수

기존 긴급도·관련도 모델과 v13 원본은 보존한다. 이번 단계는 관련도 전용 데이터 초안이며 재학습·배포를 수행하지 않는다. `v14_relevance_curation_01`은 아직 `review_pending` 상태다. 공동 학습기의 기본 데이터도 v13으로 유지하며, 미검수 초안을 자동으로 학습에 넣지 않는다.

## 확인한 라벨 기준

- 1점: 현재 목적과 무관하거나 관련성을 확인할 근거가 부족함. 근거 부족 사례의 구체적 라벨은 검수 대상이다.
- 2점: 같은 주제의 잡담·일반 소식이지만 현재 작업에 직접적인 도움은 불분명함. 사용자 확인을 받았다.
- 3점: 현재 작업에 직접 유용한 자료·요청·결과·해결 정보.
- 현재 창이 작업을 명확히 가리키면 다른 작업의 최근 창으로 덮어쓰지 않는다. 사용자가 여행 준비 현재 창과 과거 로그인 작업의 충돌 사례에서 1점을 확인했다.
- 현재 창이 `main.py`처럼 모호하면 최근 창의 구체적인 로그인 오류·인증 문서를 보조 근거로 사용해 관련도 3점을 허용할 수 있다. 사용자 확인을 받았다.
- 최근 창이 없어도 `main.py`라는 개발 분야 단서와 로그인 개발 알림이 겹치는 사례는 사용자 확인에 따라 2점이다. 특정 작업을 식별하지 못했다고 일괄적으로 1점 처리하지 않는다. 이 판단을 모든 모호한 창과 모든 업무 알림으로 확대하지 않는다.
- 같은 작업 대상의 과거판 보관 위치, 작업용 참고 링크, 같은 문서의 공유 형식 정보는 현재 행동과 정확히 같지 않아도 유용하면 3점이다. 세 경계 사례를 사용자에게 확인했다.
- 관찰 사실과 조사자 해석을 분리하는 일반 기록 양식도 현재 설정 메뉴 이해도 조사 정리에 유용하므로 3점이다. 해당 개별 사례를 사용자에게 확인했다.

이 기준은 데이터 라벨 기준이며, 모델 내부에 현재 창의 고정 가중치를 추가했다는 뜻은 아니다. 인코더·입력 형식·학습 손실은 변경하지 않았다. 정책에 동의했다고 모든 신규 제안 행의 정답 검수가 완료되는 것도 아니다.

## 기존 자료의 정리

`preparation/curate_relevance.py`는 v13 파일 해시·라벨 매핑을 검사한 뒤 관련도만 읽는다. 알려진 합성 인사말 접두·접미 표현을 제거했을 때 알림의 다른 필드, 전체 현재·최근 창 입력, 원본 라벨까지 동일한 묶음만 정리한다. 기본적으로 두 표현을 남긴다.

- 원본 관련도 10,173행 → 유지 9,813행, 반복 표현 360행 제외.
- 유지한 행의 state와 정답은 원본과 동일하며, 원본 파일을 삭제하거나 수정하지 않는다.
- 다른 창·다른 최근 창·다른 발신자·다른 시각·다른 원본 라벨은 단순 중복으로 합치지 않는다.
- 제외 사유와 남긴 사례 ID는 `review/excluded-repetitions.jsonl`에 기록한다.
- 기존에 학습한 자료는 `train_only`로 표시한다. 새 독립 테스트로 재포장하지 않는다.

`quality/audit_relevance_diversity.py`는 옛 생성 코드를 import하거나 실행하지 않고 AST로 문장 틀을 읽는다. 초기 검사에서는 2,556행·24개 틀을 인식했고, 전체 표현 변형을 포함하도록 확장한 검사에서는 9,544행·264개 틀을 인식한다. 명사만 바뀐 반복을 찾는 검수 자료이며, 작업 대상이 다른 사례를 일괄 삭제하는 근거로 사용하지 않는다. 이 제한적인 검사에 걸리지 않았다고 다른 반복이 없다는 뜻도 아니다.

반복 인사말 정리만으로 앱·최근 창 개수의 편향이 해결되지는 않는다. 기존 전체 자료의 의미 검수와 앱·맥락 구성 개선은 남아 있다. 특히 문장 틀을 일괄 축소하면 낮은 점수 자료만 줄어 클래스 구성이 더 나빠질 수 있으므로 점수·작업 분야·문맥 대비를 함께 확인해야 한다.

## 새로운 검수 초안

`generation/prepare_relevance_diversity.py`는 8개 작업 분야와 일반 단독 문자 묶음으로 52행을 만든다. 실제 사용자 데이터가 아닌 합성 제안이며 전부 `ai_proposed_unreviewed`, 분할은 `unassigned`다.

| 사례 | 행 수 |
| --- | ---: |
| 같은 현재 창에 직접 도움·주제 잡담·무관한 알림 | 24 |
| 같은 알림에서 현재 창과 과거 창의 작업이 충돌 | 8 |
| 다른 입력은 고정하고 `ㅇ`·`ㅁ`만 변경 | 4 |
| 모호한 현재 창을 최근 창의 구체적 단서로 보완 | 2 |
| 위 알림·현재 창을 고정하고 최근 창 근거만 제거 (개발 사례 2점, Word 사례는 1점 제안) | 2 |
| 알림 앱만 바꾼 통제 사례 | 6 |
| 무관한 최근 창 개수만 바꾼 통제 사례 | 6 |

본문과 현재 창 제목만으로 모든 라벨을 판단할 수 있다고 가정하지 않는다. 반대로 같은 발신자·방이라는 이유만으로 의미 없는 단문을 작업 결과로 간주하지도 않는다. 이전 대화 내용·답장 대상은 모델 입력에 없다.

원본·동일 본문·변형 사례의 묶음 ID를 유지해 분할 누수를 막는다. 기존 학습·평가 자료와 정규화 본문이 정확히 겹치면 생성을 중단한다. 이는 의미적 중복이 없다는 보증은 아니므로 이후 실제 자료와 함께 검수한다. 52행은 생성 방향을 확인하는 소규모 초안이며 최종 성능을 입증할 독립 테스트가 아니다.

현재 검수 파일의 위치는 `review/current-pilot.json`에서 확인한다. 초기 검수안은 보존하고, `main.py` 2점의 사용자 확인까지 반영한 후속 검수안은 `new/policy-confirmed-v2/`에 저장했다. 이전 검수안과 중복 합쳐 학습하지 않는다.

## 재생성

프로젝트 가상환경을 사용하고 기존 출력이 없는 새 버전 경로를 지정한다.

```powershell
.\.venv\Scripts\python.exe -m filtering_training.preparation.curate_relevance `
  --output-dir filtering_training/outputs/v14_relevance_curation_02
.\.venv\Scripts\python.exe -m filtering_training.quality.audit_relevance_diversity `
  --folder filtering_training/outputs/v14_relevance_curation_02
.\.venv\Scripts\python.exe -m filtering_training.generation.prepare_relevance_diversity `
  --output-dir filtering_training/outputs/v14_relevance_curation_02 --batch-name policy-confirmed
```

출력 데이터와 검수 기록은 `outputs/` 아래 Git 제외 대상으로 보관하고 재사용 생성·검사 코드는 Git에 포함한다. 초안 생성 뒤 아래 전체 검수 단계를 진행했다. 이후에는 실제 사용자 사례 추가, 앱·맥락 구성 개선과 그룹 단위 분할이 필요하다. 데이터 준비가 끝나기 전 대량 확장이나 모델 재학습은 진행하지 않는다.

## 남은 전체 행의 1차 의미 검수

`review/review_relevance_dataset.py`는 문장 유형의 의미를 검토한 정책과 각 행의 작업 대상·창 정보를 대조한다. 이를 9,813건을 사람이 각각 독립적으로 읽고 승인한 것으로 표현하지 않는다.

| 검수 방식 | 행 수 |
| --- | ---: |
| 검토한 문장 유형과 각 행의 대상 치환·현재/최근 창 대조 | 9,543 |
| 안전·필수 대응 41개 시나리오와 각 창 조합 대조 | 202 |
| 알림·전체 창을 개별적으로 읽은 예외 | 67 |
| 마지막으로 사용자가 확인한 기록 양식 예외 | 1 |

`review/relevance_review_policy.json`에는 사용자 확인 기준과 개별 예외 입력의 SHA256 지문을 기록한다. 예외의 입력이 바뀌면 기존 결정을 복사하지 않고 재검수 대상으로 돌린다. 옛 라벨의 다수결이나 모델 예측을 정답으로 사용하지 않는다.

전체 수정안은 `review/full-pass-02/`에 있다. 기존 9,813건의 입력은 그대로 보존하고 752건의 점수 변경을 제안했다.

- 748건: 현재 창이 같은 작업을 명확히 가리키는 잡담·근황·선택적 꾸미기 알림. 다른 최근 창 때문에 1점이던 것을 2점으로 통일.
- 3건: 직접 도움이 없는 농담 2건과 선택적 테마 1건의 기존 3점을 2점으로 수정.
- 1건: 사용자가 확인한 조사 기록 양식 안내를 2점에서 3점으로 수정.
- 9,061건: 현재 기준과 일치해 유지 제안.
- 보류 중인 행은 0건이다. 이것이 모든 실제 상황에 대한 정답 인증을 뜻하지는 않는다.

`decisions.jsonl`에는 모든 행의 기존/제안 점수·근거·검수 방식·입력 지문이 있고, `changes.jsonl`에는 수정분만 있다. `proposed.jsonl`은 변경을 반영한 별도 관련도 파일이다. 원본과 이전 검수안은 보존한다. 현재 검수안 위치는 `review/current-review.json`을 따른다. 정책 사본도 각 검수 배치에 저장한다.

검수 수정안에서도 앱 종류와 최근 창 개수만 사용한 얕은 결정 트리의 5분할 그룹 교차검증 정확도가 83.8%였다. 동일 본문 계열은 같은 그룹으로 묶었다. 이는 현재 KLUE의 성능이나 원인 분석이 아니라 데이터에 남은 지름길의 측정이다. 원본 점검과 행 수·그룹 정의가 달라 직접적인 전후 성능 비교로 해석하지 않는다.

이 전체 검수는 라벨 일관성 정리 단계다. 합성 문장 틀과 앱·창 개수의 분포 개선, 실제 사용자 자료 추가, 독립 평가 자료 준비는 남아 있다. 따라서 `training_ready`와 각 행의 `training_eligible`은 아직 false다. 모델 학습·앱 변경·커밋·푸시는 하지 않았다.

검증: 학습 도구 검사 89개와 기존 필터링 검사 35개, 총 124개가 통과했다. 수정안 9,813행의 ID·입력·원본 점수·검수 지문을 전부 대조했고, 752개 점수 변경 외의 입력 변경은 없다. 보호 파일 해시도 유지됐고 최대 입력 길이는 371토큰이다. 상세 검증 기록은 해당 배치의 `verification.json`에 있다.

```powershell
.\.venv\Scripts\python.exe -m filtering_training.review.review_relevance_dataset `
  --folder filtering_training/outputs/v14_relevance_curation_01 --batch full-pass-03
```

이 명령도 기존 배치를 덮어쓰지 않으며, 새 배치에서 현재 정책으로 검수 결과를 재생성한다.

## 반복량·앱·최근 창 구성 개선 (v15)

`preparation/balance_relevance.py`는 전체 검수 수정안을 읽어 `outputs/v15_relevance_balanced_01/`을 생성한다. 기존 모델이나 학습기의 기본 경로는 변경하지 않는다.

- 9,813행에서 4,646행을 남겼다. 150개 현재 작업, 실제 현재 창 제목 363종과 264개 표현 틀을 모두 보존했다.
- 본문 계열의 현재·최근 창 대비를 묶어서 선택한다. 같은 유형·분야에 기본적으로 본문 계열 2개를 남기되, 드문 표현·작업·점수/맥락 조합 보존에 필요하면 더 남긴다.
- 개별 검수한 68개 예외의 전체 입력은 고정했다. 안전 시나리오를 비롯한 드문 사례도 표본 축소 때문에 사라지지 않게 보존했다.
- 알림 앱은 의미상 대체 가능한 일반 채팅 앱 범위에서 점수별로 분산했다. 특정 앱·스레드·멘션을 명시하는 내용이나 고정 예외는 바꾸지 않는다.
- 최근 창은 필요한 원본 창의 최소 부분집합을 먼저 찾는다. 보조 창이 판단 근거인 행에서는 해당 창을 남긴다. 더 많은 창이 필요한 합성 변형에는 다른 작업 분야의 기존 학습용 창 제목을 사용한다. 이는 실제 사용자의 누락된 과거 창을 복원했다는 뜻이 아니다.
- 현재 창, 알림의 본문·제목·발신자·시각, 검수 점수는 그대로 유지한다. 앱과 최근 창을 바꾼 뒤 같은 검수 정책에서 점수가 유지되는지 확인한다. 이 검사는 별도 사람 검수의 대체물이 아니다.
- 구성 변경 뒤 완전히 같은 입력으로 합쳐진 6행은 별도 제외 기록에 남겼다. 라벨이 다른 중복은 허용하지 않는다.

최종 점수 분포는 1점 1,085행, 2점 1,369행, 3점 2,192행이다. 일반 채팅 앱 세 종류의 빈도는 각 점수 안에서 최대 1행 차이다. 최근 창 0~3개도 각 점수 안에서 고르게 나타나도록 하되 근거 보존과 고정 사례를 우선한다.

입력을 바꾸기 전후 **동일한 4,646행과 같은 본문 그룹 분할**로 얕은 결정 트리를 비교했다.

| 내용 없이 사용한 단서 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 알림 앱 | 70.7% | 47.3% |
| 최근 창 개수 | 72.5% | 47.2% |
| 앱 + 최근 창 개수 | 85.7% | 47.2% |
| 위 단서 + 발신자·제목·시각 | 85.7% | 62.1% |

이 표의 최다 클래스 기준은 47.2%다. 앱·창 개수만으로 점수를 맞히는 지름길은 줄었지만, 다른 합성 흔적까지 사라진 것은 아니다. 전체 원본 9,813행의 앱·창 개수 검사 83.8%와 위 변경 전 85.7%는 표본이 달라 같은 수치가 아니다. KLUE의 정확도 향상이나 실제 앱 성능을 측정한 표도 아니다.

## 사용자가 제공한 CSV와 실제 입력 검수 (v16)

사용자가 `filtering_training/data/`에 제공한 CSV는 177행이다. 이 경로의 CSV와 모든 변환 결과는 Git 제외 대상이며, 개인 알림 내용·이름·창 제목을 이 문서나 코드에 복사하지 않는다. 원본 CSV는 수정하지 않았다.

`preparation/prepare_real_relevance.py`는 다음 사용자 확인을 적용한다.

같은 앱·제목의 가까운 시각과 같은 비어 있지 않은 본문을 보수적으로 연결한 임시 묶음은 46개이며, 가장 큰 묶음은 47행이다. 이는 독립성이 입증된 대화·시나리오 분할이 아니다. 반응 한 글자처럼 흔한 본문 때문에 다른 대화가 보수적으로 연결될 수도 있으므로 최종 분할 전에 검수한다. 현재 모든 행의 split은 unassigned다.

### 적은 답변으로 진행하는 로컬 검수 카드

`review/prepare_real_review_packets.py`는 개인 출력 폴더의 검수 계획을 읽어 전체 입력을 함께 볼 수 있는 HTML, Markdown, 카드 목록 CSV를 만든다. 실제 알림 내용과 번호별 계획은 코드에 넣지 않고 Git에서 제외된 outputs에만 보관한다. 기존 모델 예측은 화면에 표시하지 않는다.

현재 `review/user-packets-01/검수하기.html`에는 경계 사례 16행을 13개 카드로 묶었다. 먼저 1차 A~F 여섯 카드(9행), 이어 2차 다섯 카드와 3차 두 카드를 확인한다. 이미 별도 보류한 모의 생성기 전경창 15행은 재질문하지 않는다. 나머지 146행은 기존 제안을 유지하며, 카드에서 빠졌다는 이유로 사용자 정답이 되지는 않는다.

점수는 미리 선택하지 않는다. 사용자가 선택한 카드만 `A=2, B=3` 형식으로 복사하거나 개인 알림 내용을 제외한 답변 JSON으로 저장한다. 화면의 일괄 선택 버튼은 현재 묶음에서 아직 선택하지 않은 카드에만 제안을 채운다. 같은 카드에 속한 원본은 같은 답이 적용되므로 서로 다른 점수라면 보류와 번호별 메모를 사용한다. 페이지를 열거나 답을 저장하는 행위는 원본 CSV·제안 데이터셋을 수정하지 않는다.

답변 반영은 `--packet <packet.json> --answers <답변.json> --batch <새 배치>`로 수행한다. 카드 지문·입력 지문을 검증하고 현재 최신 검수 이력 위에 명시적으로 답한 원본만 사용자 검수로 표시한다. 앞선 묶음의 답변은 보존하고 미응답을 승인하지 않는다. 답변 후에도 학습 허용 및 데이터 분할은 별도 작업이다.

## 사용자 답변 반영과 개발용 후보 분할 — 2026-11-11

13개 카드에 대한 사용자 답변은 정확한 입력 지문에 연결해 원본 16행에 반영했다. 1차 A~F는 3·2·2·3·3·3, 이어 G~M은 2·2·3·1·2·1·1이다. 마지막 두 보류 사례도 사용자 선택에 따라 1점이다. 각 배치는 원본 입력과 이전 답변을 보존한다. 특정 카드 답변을 모든 프로젝트·모든 수치 알림에 적용하는 일반 규칙으로 확대하지 않았다.

실제 CSV의 최신 검수 포인터는 `v16_real_relevance_review_01/review/current-review.json`이다. 177행 중 점수가 있는 162행의 분포는 1점 81·2점 51·3점 30이며, 모의 생성기 전경창 15행은 보류한다. 이 중 직접 사용자 확인 점수는 16행이고 나머지 146행은 assistant 제안이다. CSV에는 자연 발생 알림뿐 아니라 수동·모의 시험 알림도 섞여 있으며, 그 출처 표시는 유지한다.

`preparation/prepare_relevance_experiment.py`로 v15 구성 개선본 4,646행, 새 합성 시나리오 52행, CSV 제안 162행을 합쳐 `outputs/v17_relevance_experiment_01`에 개발용 후보를 만들었다. 점수나 입력 내용은 변경하지 않았고 긴급도 데이터·모델도 변경하지 않았다.

| --- | ---: | ---: | ---: | ---: |

묶음은 원본 body group·새 합성 시나리오·완전히 같은 모델 입력·정규화한 본문·알려진 문구 포장 제거 후 같은 본문을 연결한다. 12자 이상 본문은 문자 3~5-gram TF-IDF 코사인 유사도 0.92 이상도 연결하며, 검출된 연결은 19개다. 유사도는 분할 누출을 줄이는 용도로만 쓰고 정답을 바꾸지 않는다. 묶음 전체를 함께 나누므로 같은 본문이 다른 작업에서 서로 다른 정답을 가지는 대비 사례도 분리되지 않는다.

4,860행에서 완전히 같은 입력의 정답 충돌과 앱·발신자·시각을 제외한 같은 알림·창 내용의 점수 충돌은 없었다. 완전히 같은 입력 중복도 없었다. 이 검사는 의미가 비슷한 모든 알림의 정답을 사람이 재확정했다는 뜻은 아니다. 특히 다른 작업 문맥에서 점수가 달라지는 것은 자동 오류로 취급하지 않는다.

`quality/verify_relevance_experiment.py`는 출처와 출력 해시·전체 ID·보류 제외 내역·점수와 입력 보존·출처 묶음·분할 중복·토큰 길이를 재검증한다. 묶음, 정확한 입력, 정규화 본문, 검출된 유사 문장 연결의 분할 간 중복은 각각 0이다. 최대 입력은 371토큰이다. 어휘 유사도 검사로 모든 바꿔 쓴 문장이나 의미 유사성을 찾아냈다고 주장하지 않는다.

```powershell
.\.venv\Scripts\python.exe -m filtering_training.preparation.prepare_relevance_experiment `
  --real filtering_training/outputs/v16_real_relevance_review_01/review/user-review-round-02-03/proposed.jsonl `
```

이 분할은 assistant 제안이 포함된 후보이며 `training_ready=false`다. 기존 공동 학습 코드의 기본 입력 경로로 연결하지 않았고 재학습을 시작하지 않았다. 다음 학습 작업에서는 관련도 전용 모델·후보 점수 사용 조건·실험 설정을 명시하고 이 개발용 검증으로 방향을 비교한다. 최종 성능은 새 수집 구간·다른 프로젝트의 별도 자료로 평가한다.

커밋 시점은 이 데이터 정리·검수·분할 도구가 검사에 통과한 뒤다. 현재 `feature/filtering-short-message-data`를 그대로 사용하고, 관련도 전용 학습·모델 파일 생성은 다음 작업 단위로 둔다. 실제 CSV·출력 JSONL·개인 검수 카드는 기존 Git 제외 규칙을 유지한다. 사용자 요청 없이 커밋·푸시하지 않는다.

검증: 학습 도구 검사 125개와 기존 필터링 검사 35개, 총 160개가 통과했다. 새 분할 검사는 충돌 검출, 다른 작업 문맥의 합법적인 정답 차이, 같은 문장·시나리오·유사 문장 연결, 실제 자료의 학습 쪽 고정, 분할 재현성, 보류 제외, 출처 보존과 덮어쓰기 거부를 포함한다.
