# Gemma 4 E2B 브리핑 적용 검증

## 배포 후보

브리핑 후보는 [Google Gemma 4 E2B IT QAT Q4_0 GGUF](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf)의 텍스트 모델 `gemma-4-E2B_q4_0-it.gguf`다. 검증 파일은 3,349,516,256바이트이며 SHA-256은 `fa401b55b07ee70a54c6dae3903c783a6e65064312529ea57175cb5f8dec6634`다. 프로젝트의 AI Hub 120건 LoRA 어댑터 적용은 별도 실험이었다.

AI Hub 검증 10건에서 추가 학습 모델은 평가기의 구조화 출력 성공이 0/10에서 9/10으로 늘었다. 기본 모델은 10건 모두 JSON을 마크다운 코드 블록으로 감쌌다. 추가 학습 모델의 일부 응답은 핵심 사실을 누락하거나 발화 한 줄을 그대로 가져왔다. 이 결과를 바탕으로 공식 GGUF와 생성 단계의 JSON 제약을 앱 연동 후보로 선택했다.

## 로컬 연동

Gemma GGUF를 지원하는 llama-server에 모델을 로드하고 `127.0.0.1`에 바인딩한다. 검증은 CPU 스레드 6개, 문맥 4096 토큰, reasoning off 설정에서 진행했다. [클라이언트 PR #61](https://github.com/AIoish/ALTONG_client/pull/61)의 빌드를 실행할 때 앱 프로세스의 `ALTONG_GEMMA_PORT`에 해당 포트를 지정한다.

클라이언트가 시스템 및 사용자 메시지와 JSON 스키마를 보내면 서버가 GGUF의 Gemma 채팅 템플릿을 적용한다. 응답 객체는 `primary_category`와 `summary_lines` 두 키를 사용한다. 클라이언트는 허용 카테고리 하나와 요약 1~3줄, 줄당 160자 이하를 검사한다.

## 확인한 결과

- 동일한 로컬 사례 5건에서 생성 스키마 적용 전 2건, 적용 후 5건이 코드 블록 없는 JSON 규격을 지켰다. 적용 후에도 오후 시각을 오전으로 바꾸거나 금액을 빠뜨린 사례가 있었다.
- 2026년 11월 20일, 수정된 클라이언트에서 로컬 테스트 파이프로 모의 리허설 알림 6건을 넣었다. 6건이 모두 차단됐고, 브리핑에 305호로 장소 변경, 다음 날 오후 3시부터 3시 반까지 리허설, 민지 발표, 지훈의 당일 오후 8시 PDF 제출이 표시됐다.
- 일정 카드에서 2026년 11월 21일 15:00–15:30 (한국 시간), 305호가 표시됐다. Windows 알림 자체의 수신과 캘린더 저장은 이 검증 범위에 포함되지 않았다.
