# 브리핑 분류·요약 기준 (v8)

이 기준은 필터링 모델의 점수가 아니라 브리핑 그룹의 본문과 핵심 목적에 적용합니다.
카테고리와 일정 유무는 별개입니다. 업무 마감·개인 진료도 일정 정보가 있으면 추출합니다.

| 카테고리 | 기준 |
| --- | --- |
| 긴급 업무 | 서비스 장애, 배포 실패, 배치 중단과 그 복구·롤백 결과 |
| 일반 업무 | 업무 요청, 자료 제출·마감·공유·검토·완료 |
| 일정/회의 | 회의, 행사, 교육, 오리엔테이션의 예정·변경·취소 |
| 시스템/보안 | 로그인, 계정, 비밀번호, 기기 차단 및 시스템·시설 점검 |
| 개인 중요 | 개인 진료·예약·여행·결제·환불·배송·구독 갱신 |
| 개인 일반 | 일상 대화, 개인 감상과 소식 |
| 광고/홍보 | 상품 할인, 쿠폰, 홍보 |
| 기타 | 분실물 보관 등 위 기준에 해당하지 않는 안내 또는 근거 부족 |

시설 점검을 시스템/보안으로 묶는 것은 이 프로젝트의 명시적 선택입니다.
팀 기준을 바꾸면 프롬프트와 학습·검증·평가 정답을 함께 변경해야 합니다.
시나리오별 변경 목록은 `prepare_category_dataset.py`의 `LABEL_OVERRIDES`에서 확인합니다.
평가 예측값을 보고 정답을 자동으로 바꾸지 않습니다.

## 요약

- 최대 3줄은 상한입니다. 짧은 요청은 한 문장으로 충분합니다.
- 대상, 필요한 행동, 제출물, 명시된 날짜·시간·위치를 보존합니다.
- 같은 사건은 최신 상태만 남깁니다. 최신 메시지가 보탠 정보는 앞 내용과 합칩니다.
- 분류 설명, 의미 없는 마감 문장, 원문에 없는 정보를 추가하지 않습니다.
- 카카오톡 `title`은 방 이름이며 장소나 업로드 위치로 해석하지 않습니다.
- 알림 수신 시각을 원문에 없는 일정 시각으로 바꾸지 않습니다.

## 일정의 what

원문에 명시된 안건·내용을 우선하고, 카카오톡에서는 일정 명사구를 추출합니다.
예: `참석자는 개발팀입니다. 회의 내일 할게요.` → `개발팀 회의`.
방 이름이나 발신자 이름으로 일정을 꾸며내지 않습니다. 명확한 안건이 없으면
원문에 나온 `회의`, `예약` 같은 일반적인 이름만 사용합니다.
날짜·시간·참석자·장소는 기존 별도 필드로 보존합니다.

## 검증 및 비교

v7 데이터는 `data/category_briefing/`, v8은 `data/category_briefing_v8/`에 보존합니다.
v8은 기존 사례를 정책에 맞춰 변환하고 학습 80건·검증 16건을 추가합니다.
별도 `short_request_evaluation.jsonl` 8건은 학습·검증과 다른 대상을 사용합니다.
모델에는 최대 3줄을 허용하되 이 짧은 요청 평가에서는 한 줄만으로 충분한지 확인합니다.
필수 사실과 금지 표현도 확인하지만 자동 평가는 모든 의미 왜곡을 검출하지 못하므로
원문과 출력의 수동 검토가 필요합니다.

입력과 정답 기준이 변경됐으므로 v7의 이전 점수와 v8의 새 점수를 직접 비교하지 않습니다.
두 어댑터를 동일한 v8 평가 데이터·프롬프트·고정 생성 방식으로 다시 평가합니다.

## 재학습 없는 v8 분류 교정

`category_correction.py`는 모델 응답을 파싱한 뒤 원문에서 복수 신호가 확인된 경우에만
대표 카테고리를 교정합니다. 후보가 서로 다른 카테고리이면 우선순위로 강제 선택하지 않고 모델 판단을 유지합니다.
카카오톡 title은 방 이름이므로 제외하며 발신자, 필터링 라벨·점수, 평가 정답은 사용하지 않습니다.
규칙/모델이 모두 틀릴 수 있습니다. 요약 문장 자체는 변경하지 않으며, 구조화 출력 실패를 숨기지도 않습니다.

원본 모델 정확도와 교정 후 서비스 정확도는 구분해 보고합니다. 기본 평가에는 교정이 적용되고
`--no-category-correction`으로 원본 분류를 재현할 수 있습니다. GGUF 실행 시 별도 교정 코드 연결이 필요합니다.
